# Golang URL Shortener

Высокопроизводительный сервис для сокращения ссылок, написанный на Go. Проект построен на принципах чистой архитектуры (Clean Architecture) и поддерживает гибкое переключение между различными хранилищами данных (PostgreSQL и In-Memory) с помощью переменных окружения.

## Основные возможности

- **Гибкое хранилище**: Поддержка PostgreSQL (с миграциями) и In-Memory (хранение в оперативной памяти). Выбор осуществляется через переменную `STORAGE_TYPE`.
- **Чистая архитектура**: Разделение на слои (Domain, Service, Transport, Repository).
- **Обработка коллизий**: Встроенный механизм retry при генерации коротких кодов (если код уже занят, сервис сгенерирует новый).
- **Docker-поддержка**: Полная контейнеризация приложения и базы данных с помощью `docker-compose`.
- **Логирование**: Структурированное логирование на базе `uber-go/zap` с записью в файл и консоль.
- **Тестирование**: Покрытие unit-тестами (domain, repository, service, transport).

## Требования к версиям

Для успешной сборки и запуска проекта убедитесь, что на вашей машине установлены следующие инструменты:

- **Go (Golang)**: **версия 1.22 или выше** (обязательно, так как в проекте используется новый синтаксис маршрутизации `http.ServeMux` и `r.PathValue()`).
- **Docker Engine**: версия **20.10.0+**.
- **Docker Compose**: версия **v2.0.0+** (команда должна вызываться как `docker compose`, а не `docker-compose`).
- **Make**: Утилита для запуска команд из `Makefile`.
  - *Для пользователей Windows*: `make` нет в стандартной поставке. Вы можете установить его через пакетные менеджеры (например, `choco install make` или `winget install GnuWin32.Make`), либо запускать команды из консоли Git Bash / WSL.
- **PostgreSQL**: версия **16+** (при использовании локальной БД без Docker; в Docker используется образ `postgres:18`).

## Использование Makefile

В проекте есть `Makefile`, который автоматизирует рутинные задачи: запуск контейнеров, миграции и локальную разработку.

> **Важно:** Команды `make` следует запускать из корневой директории проекта (там, где лежит сам `Makefile`).

### 1. Управление окружением (База данных)
* `make env-up` — запускает контейнер с PostgreSQL в фоновом режиме. Используется перед миграциями или локальным запуском.
* `make env-down` — останавливает контейнер с PostgreSQL (данные сохраняются).
* `make env-cleanup` — останавливает БД и **полностью удаляет** папку с данными (`out/pgdata`). Полезно, если нужно начать с чистой базы.

### 2. Работа с миграциями
* `make migrate-up` — применяет все непримененные SQL-миграции из папки `migrations/` к базе данных.
* `make migrate-down` — откатывает последнюю примененную миграцию.
* `make migrate-create seq=init` — создает два новых пустых файла миграции (up/down) с указанным именем (`init`).

### 3. Управление приложением (Docker)
* `make app-up-postgres` — собирает Docker-образ приложения и запускает его вместе с базой данных (`STORAGE_TYPE=postgres`).
* `make app-up-memory` — собирает и запускает приложение с In-Memory хранилищем (без использования базы данных).
* `make app-down` — останавливает и удаляет все запущенные контейнеры проекта.

### 4. Локальная разработка (без Docker для приложения)
* `make url-shortener-run` — запускает приложение локально через `go run`. Перед этим он создает папку `out/logs` для записи логов и выполняет `go mod tidy`.
  * *Примечание:* Для этого режима база данных должна быть запущена отдельно (`make env-up`), а в `.env` файле переменная `HOST` должна быть равна `localhost`.

## Примеры запуска

Ниже представлены два независимых сценария запуска: с использованием базы данных PostgreSQL и с хранением данных в оперативной памяти (In-Memory).

### Вариант 1: Запуск с PostgreSQL

В этом режиме данные сохраняются на диск и не теряются при перезапуске контейнеров.

```bash
# 1. Создаем файл конфигурации из шаблона
cp .env.example .env

# 2. Собираем и запускаем приложение вместе с базой данных
# (Docker Compose автоматически поднимет контейнер с Postgres, так как он указан в зависимостях)
make app-up-postgres

# 3. Применяем миграции (создаем таблицы в базе данных)
make migrate-up
```

---

### Вариант 2: Запуск с In-Memory

В этом режиме приложение не требует базы данных. Все ссылки хранятся в оперативной памяти и удаляются при перезапуске контейнера. Отлично подходит для быстрого тестирования или демонстрации без настройки БД.

```bash
# 1. Создаем файл конфигурации из шаблона
cp .env.example .env

# 2. Собираем и запускаем только контейнер с приложением
# (База данных запускаться не будет, миграции не требуются)
make app-up-memory
```
